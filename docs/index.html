    How this maps to Tari Ootle

    Ootle Forge is a real Rust #[template] for the Tari Ootle engine (see the template/ directory of the repository). This page is a walletless simulation of that template: the JavaScript engine here implements the same constants and rules — same gather amount, same forge cost and fee, same tier odds (62% / 26% / 9% / 3%), same melt values — so what you play here is what the template does on-chain.

    HereOn Ootle
    Gatherforge.gather() — mints 5 EMBER. Only the Forge component may mint EMBER; the rule is locked at creation.
    Forge a Relicforge.forge(embers, fee) — burns exactly 5 EMBER, banks a 1 TARI fee, rolls a tier from engine entropy, mints one Relic NFT.
    Ascendforge.ascend(a, b, c) — burns three same-tier Relics, mints one of the next tier. Legendaries cannot ascend.
    Meltforge.melt(relic) — burns one Relic, mints back 2 / 6 / 18 / 54 EMBER by tier.
    Statisticsforge.stats() — read-only counters plus the fee vault balance.
    Feesforge.withdraw_fees() — only the holder of the Forge admin badge NFT may call it.

    Honest notes

    • The template is not yet published to Esmeralda or mainnet; this demo is a simulation and is labelled as one. The template itself is proven by engine tests (cargo test in template/) that run it in the real Ootle engine in-process.
    • On-chain, the tier roll uses the engine's transaction entropy (random_bytes); here it uses local randomness with identical odds. Game-grade randomness — fine for collectibles, not for money gambling.
    • Relics are ordinary Ootle NFTs: once minted to your account they are yours — transferable and checkable by any app. The Forge can never mint a Relic outside forge/ascend, and nobody can change its rules: the component has no owner and locked resource rules.
    • Your collection is saved in this browser (localStorage).
